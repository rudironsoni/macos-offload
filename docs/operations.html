Common operations

These flows cover setup, mount verification, Apple-tool checks, and rollback.

Install on a new machine

  1. Mount the external volume.
  2. Set MACOS_OFFLOAD_ROOT to a path on that volume.
  3. Run repair --dry-run and read the human-readable plan.
  4. Run user repair with --load.
  5. Retire any legacy system daemon, then restart once.
  6. Run doctor --strict.
export MACOS_OFFLOAD_ROOT="/Volumes/YourExternalVolume"
macos-offload repair --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope user --install-shims --dry-run
macos-offload repair --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope user --install-shims --load
sudo macos-offload mounts uninstall --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope system --unload --on-reboot
macos-offload doctor --root "$MACOS_OFFLOAD_ROOT" --require-shims --strict

Enable APFS mount mode

macos-offload mounts install --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope user --dry-run
macos-offload mounts install --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope user --load
macos-offload mounts status --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope all

Normal output is intentionally short. Add --verbose to install, repair, uninstall, or status commands when you need the raw command list or every individual mount check.

Verify in a scratch root

macos-offload mounts verify \
  --scratch-root "/Volumes/YourExternalVolume/macos-offload-verify" \
  --mode user

The command creates disposable sparsebundles, mounts them, checks status, unmounts them, and removes the scratch run directory.

Run Apple tools without shims

PATH="/usr/bin:/bin:/usr/sbin:/sbin" /usr/bin/xcrun simctl list devices available
PATH="/usr/bin:/bin:/usr/sbin:/sbin" /usr/bin/xcodebuild -version

If APFS mount mode is working, these commands should see the mounted Apple paths without shim involvement.

Recreate a broken simulator

Repair the managed device-store mount first, then recreate the simulator inside that mounted Apple path. Do not copy simulator folders between device stores. 

macos-offload mounts repair \
  --root "$MACOS_OFFLOAD_ROOT" \
  --home "$HOME" \
  --scope user \
  --load

macos-offload sim reset \
  --name Orlix-iPhone-15-Pro-Max \
  --device-type com.apple.CoreSimulator.SimDeviceType.iPhone-15-Pro-Max \
  --runtime com.apple.CoreSimulator.SimRuntime.iOS-26-5 \
  --verify \
  --screenshot /tmp/orlix-verify.png

The verification step waits for bootstatus, runs /bin/echo responsive inside the simulator, and captures a screenshot. A listed device is not enough proof by itself.

Back out user mount mode

macos-offload mounts uninstall --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope user --unload

Retire legacy system mount mode

sudo macos-offload mounts uninstall --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope system --unload --on-reboot

This removes both historical root jobs without detaching a parent that may contain an active CoreSimulator runtime mount. Restart to release the old sparsebundles safely.
