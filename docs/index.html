macOS developer storage

Move Xcode storage off the internal disk.

macos-offload mounts external APFS sparsebundles at the paths Xcode and CoreSimulator already use.

Start setup Read commands

Why this exists

Xcode installs, simulator device sets, DerivedData, and archives can take hundreds of gigabytes. This tool uses APFS mounts for user-owned paths while CoreSimulator system paths stay on the internal volume.

Apple paths stay normal

Tools still see normal user paths such as ~/Library/Developer/CoreSimulator/Devices.

No symlinked mount parents

The mount manager rejects symlinked Apple paths because CoreSimulator can reject them.

Fails before it guesses

If a managed path is mounted from an unexpected backend, the tool stops and asks you to inspect it.

Repair is repeatable

One user LaunchAgent reconciles UUID-bound mounts from Disk Arbitration events.

Basic setup

export MACOS_OFFLOAD_ROOT="/Volumes/YourExternalVolume"

macos-offload repair \
  --root "$MACOS_OFFLOAD_ROOT" \
  --home "$HOME" \
  --scope user \
  --install-shims \
  --dry-run

macos-offload repair \
  --root "$MACOS_OFFLOAD_ROOT" \
  --home "$HOME" \
  --scope user \
  --install-shims \
  --load

macos-offload doctor \
  --root "$MACOS_OFFLOAD_ROOT" \
  --require-shims \
  --strict

Mount mode

Use mounts when you want the default Apple paths backed directly by APFS sparsebundles: 

macos-offload mounts install --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope user --load
macos-offload mounts status --root "$MACOS_OFFLOAD_ROOT" --home "$HOME" --scope all
CoreSimulator system paths stay internal. Retire legacy root mount jobs with mounts uninstall --scope system --unload --on-reboot, then restart once.
